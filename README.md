# gccity

카카오톡 **오픈채팅방을 따라가며 대화를 모으는** 단일 사용자용 콘솔.

- **읽기 전용이다.** 봇이 카톡에 한 글자도 쓰지 않는다. 방 사람들은 봇의 존재를 알 수 없다.
- **방 선택은 대시보드에서만 한다.** 방 안에 `#등록` 같은 명령을 치지 않는다.
- 지금은 방 하나를 보지만, 팔로우를 여러 개 켜면 그대로 여러 방이 된다.

설계 배경과 원칙은 [`CLAUDE.md`](./CLAUDE.md). 코드를 건드리기 전에 그걸 먼저 읽을 것.

---

## 세팅

### 1. Supabase

`speciai-kakao-bot` / linktalk 과 **다른 프로젝트**를 새로 만든다(이유는 CLAUDE.md).
SQL Editor 에 `supabase/migrations/0001_init.sql` 을 붙여넣고 실행한다.

### 2. 환경변수

`.env.example` 를 `.env.local` 로 복사해 채운다.

| 이름 | 설명 |
|---|---|
| `NEXT_PUBLIC_SUPABASE_URL` | 새 Supabase 프로젝트 URL |
| `SUPABASE_SERVICE_ROLE_KEY` | service-role 키. 브라우저로 안 나간다 |
| `GCCITY_INGEST_TOKEN` | 봇과 공유하는 비밀. 아무 긴 문자열 |
| `GCCITY_PASSWORD` | 대시보드 비밀번호 |
| `GCCITY_DISCOVERY_MINUTES` | 방 찾기 모드 지속 시간(분). 기본 30 |

```bash
npm install
npm run dev      # http://localhost:3100
```

### 3. 봇

1. 메신저봇R 설치 → **알림 접근 권한** 허용 → 배터리 최적화 제외
2. 봇 새로 만들기 → `bot/gccity-bot.js` 전체 붙여넣기
3. 맨 위 3줄(`CONFIG_ENDPOINT` · `INGEST_ENDPOINT` · `TOKEN`)을 채운다
4. 컴파일 ON. 로그 첫 줄에 `gccity: 시작 …` 이 뜨면 올라간 것이다

폰 설정 체크리스트는 CLAUDE.md "폰 설정이 절반이다" 참조. 하나라도 빠지면 아무것도 안 들어온다.

## 쓰는 법

1. 대시보드에서 **[방 찾기 모드]** 를 켠다
2. 최대 60초 뒤 봇이 그 설정을 받아간다
3. 목표 오픈채팅방에서 메시지가 오면 왼쪽 **후보** 목록에 뜬다
   (발신자 이름과 본문 앞 12자로 알아본다)
4. 그 방을 눌러 **[이 방 팔로우]**
5. **방 찾기 모드를 끈다** — 안 끄면 30분 뒤 자동으로 꺼진다
6. 그 시점부터 오는 대화가 오른쪽 타임라인에 몇 초 안에 쌓인다

> 팔로우 이전의 대화는 저장되지 않는다. 알림은 지나가면 끝이라 되살릴 방법이 없다.

방 찾기 모드가 켜져 있는 동안에는 **개인 카톡방도 후보로 올라온다**(발신자 + 앞 12자).
목표 방을 찾았으면 바로 끄고, 필요 없는 후보는 [지우기] 로 정리한다.

## 수집이 멈췄을 때

| 증상 | 봄 |
|---|---|
| 봇 상태가 **끊김** | 폰을 본다. 메신저봇R 이 죽었거나 절전에 들어갔다 |
| 봇 상태는 **정상**인데 타임라인이 안 는다 | 방이 조용한 것이거나, 방 열쇠가 바뀐 것이다 |
| "팔로우 방이 6시간 조용하다" 배너 | 방 찾기 모드를 켜서 같은 방이 **새 후보**로 뜨는지 본다. 뜨면 그게 새 열쇠다 — 팔로우를 옮긴다 |
| 로그에 **성공 줄과 실패 줄이 같이** 뜬다 | 재컴파일이 남긴 좀비 루프다. 봇을 껐다 켜거나 메신저봇R 을 완전 종료 후 재실행한다. `xn--<>-…` 주소가 보이면 주소를 채우기 전 옛 스크립트가 살아 있는 것이다 |

폰에서 직접 확인하려면 `bot/observe.js` 를 임시로 올린다. 서버 없이 돌면서 알림의
`tag`·`id` 를 찍고, 재부팅 전후로 대조해 준다.
