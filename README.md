# gccity

카카오톡 **오픈채팅방을 따라가며 대화를 모으는** 단일 사용자용 콘솔.

- **읽기 전용이다.** 봇이 카톡에 한 글자도 쓰지 않는다. 방 사람들은 봇의 존재를 알 수 없다.
- **방 선택은 대시보드에서만 한다.** 방 안에 `#등록` 같은 명령을 치지 않는다.
- 방은 **`channelId`**(카톡이 방에 붙인 고유 번호)로 가른다. 그 숫자를 대시보드에 치면 끝이다.
  이름은 따로 붙이고 언제든 바꾼다 — 숫자를 방 이름으로 쓰면 화면이 못 읽게 된다.
- 대화와 **사진**은 봇이 모은다. **파일(PDF·한글 등)은 이름만** 남고, 실물은 사람이 자료실에
  끌어다 넣는다.
- 지금은 방 하나를 보지만, 팔로우를 여러 개 켜면 그대로 여러 방이 된다.

설계 배경과 원칙은 [`CLAUDE.md`](./CLAUDE.md). 코드를 건드리기 전에 그걸 먼저 읽을 것.

## 세팅

### 1. Supabase

`speciai-kakao-bot` / linktalk 과 **다른 프로젝트**를 새로 만든다(이유는 CLAUDE.md).
SQL Editor 에 `supabase/migrations/` 의 파일을 **번호순으로** 붙여넣고 실행한다
(`0001_init.sql` → … → `0007_digest.sql`).
`0003` 은 이미 쓰던 프로젝트에도 안전하다 — 두 번 돌려도 되고, 기존 방·대화를 지우지 않는다.

### 2. 환경변수

`.env.example` 를 `.env.local` 로 복사해 채운다.

| 이름 | 설명 |
|---|---|
| `NEXT_PUBLIC_SUPABASE_URL` | 새 Supabase 프로젝트 URL |
| `SUPABASE_SERVICE_ROLE_KEY` | service-role 키. 브라우저로 안 나간다 |
| `GCCITY_INGEST_TOKEN` | 봇과 공유하는 비밀. 아무 긴 문자열 |
| `GCCITY_PASSWORD` | 대시보드 비밀번호 |
| `GCCITY_DISCOVERY_MINUTES` | 방 찾기 모드 지속 시간(분). 기본 30 |
| `ANTHROPIC_API_KEY` | 카톡 대화 → 민원 초안 분석용. **없으면 분석만 안 돈다**(fail-closed). 나머지 기능은 그대로 |
| `GCCITY_DIGEST_HOURS` | 분석 창 길이(시간). 기본 6 |
| `GCCITY_DIGEST_MODEL` | 분석 모델. 기본 `claude-opus-5` |
| `CRON_SECRET` | 민원 출처 자동 수집·카톡 분석용. Vercel 이 cron 요청에 `Bearer` 로 실어 보낸다. **없으면 자동 수집이 아예 안 돈다**(fail-closed) — 손으로 [지금 긁기] 는 된다 |

```bash
npm install
npm run dev      # http://localhost:3100
```

### 3. 봇

1. 메신저봇R 설치 → **알림 접근 권한** 허용 → 배터리 최적화 제외
2. 봇 새로 만들기 — 반드시 **API2 프로젝트**로 만든다.
   `channelId` 는 API2 에서만 오고, 레거시로는 방을 가를 수단이 아예 없다.
3. `bot/gccity-bot.js` 전체 붙여넣기 → 맨 위 4줄
   (`CONFIG_ENDPOINT` · `INGEST_ENDPOINT` · `PHOTO_ENDPOINT` · `TOKEN`)을 확인한다
4. 컴파일 ON. 로그에 이렇게 뜨면 올라간 것이다:

```
━━━ gccity 2026-08-20-ch1 시작 — 읽기 전용. 카톡에 아무것도 쓰지 않는다 ━━━
gccity: 메시지 훅 등록 (API2) — 방은 channelId 로만 가른다
gccity: 알림 훅 등록 — 첨부(사진·파일 이름) 전용
```

`★ API2 가 아니다` 가 뜨면 레거시 프로젝트로 만든 것이다. 다시 만들어야 한다
(대시보드 봇 상태 줄에도 `⚠️ API2 꺼짐` 으로 뜬다).

폰 설정 체크리스트는 CLAUDE.md "폰 설정이 절반이다" 참조. 하나라도 빠지면 아무것도 안 들어온다.

## 쓰는 법

### channelId 를 안다면 (기본)

1. 대시보드 **[방 고르기]** 탭에 그 방의 **channelId** 와 이름을 넣고 **[방 등록]**
   - 숫자는 폰의 다른 봇 로그에 `ch=[18409238712050393]` 처럼 찍힌다. 통째로 붙여넣어도
     숫자만 뽑아 쓴다.
   - `bot/observe.js` 를 잠깐 올리면 `[CH]` 줄에 이 폰으로 오는 방들의 channelId 가 찍힌다.
2. 최대 60초 뒤 봇이 설정을 받아간다 → 그때부터 **[대화]** 탭에 쌓인다

이 길은 개인 카톡을 **한 건도** 서버로 올리지 않는다. 이름은 비워도 되고, 나중에 [이름]
버튼으로 언제든 바꾼다.

### 숫자를 모른다면 (방 찾기 모드)

1. **[방 찾기 모드]** 를 켠다 → 최대 60초 뒤 봇이 그 설정을 받아간다
2. 목표 방에서 메시지가 오면 **후보** 목록에 뜬다(발신자 + 본문 앞 12자로 알아본다)
3. 그 방을 눌러 **[이 방 팔로우]**
4. **방 찾기 모드를 끈다** — 안 끄면 30분 뒤 자동으로 꺼진다

> **방 찾기를 켠 뒤부터 팔로우까지 사이의 대화도 함께 올라온다.** 봇이 후보 방의 본문을
> 폰 안에만 담아두다가, 팔로우하는 순간 그 방 몫만 보낸다.
> 다만 **그 이전의 대화는 되살릴 수 없다.**

방 찾기 모드가 켜져 있는 동안에는 **개인 카톡방도 후보로 올라온다**(발신자 + 앞 12자).
목표 방을 찾았으면 바로 끄고, 필요 없는 후보는 [지우기] 로 정리한다.

### 민원실

과천 민원 게시글을 한 곳에 모아 **새 민원 → 확인 중 → 처리 완료** 로 상태를 따라간다.
자료실과 달리 **방에 매이지 않는다** — 팔로우 방을 바꿔도 같은 목록이다.

담는 길이 셋이다.

1. **붙여넣기** — 게시판 목록을 브라우저에서 복사해 상자에 넣으면 한 줄이 한 건이 된다.
   댓글 수 `[3]`·새 글 배지 `N`·아이콘은 알아서 뗀다.
   ★ **네이버 카페는 이 길뿐이다.** `cafe.naver.com/robots.txt` 가 모든 봇에 `Disallow: /`
   라 서버가 긁지 않는다(과천시청 `/portal/bbs/`·`/jumin/bbs/` 도 마찬가지로 막혀 있다).
2. **출처 크롤** — RSS·게시판 주소를 등록하면 서버가 주기적으로 읽는다.
   등록할 때 robots.txt 를 먼저 보고, 막힌 곳이면 **등록 자체를 거부하고 사유를 알려준다.**
   자동 수집은 매일 아침 8시(`vercel.json` 의 cron), 급하면 **[지금 긁기]**.
3. **카톡에서 담기** — [대화] 탭에서 말풍선에 마우스를 올리면 뜨는 **[민원]** 버튼.
   원문 전체가 함께 저장되고, 담당 부서·완료 예정일이 본문에서 자동으로 뽑힌다.
4. **카톡 자동 분석** — 매일 아침 9시, 그동안 쌓인 대화를 모델이 읽고 민원을 **초안**으로 넣는다
   (`AI 초안` 배지). 사람이 카페와 대조해 [확정] 하거나 [지우기] 한다.
   급하면 민원실의 **[지금 분석]** 버튼.

같은 글은 몇 번 담아도 한 건이다(주소 → 없으면 출처+제목 해시). 다시 긁어도
**사람이 바꿔둔 상태·메모·분류는 덮이지 않는다.**

### 사진과 파일

- **사진** — 봇이 알림에서 꺼내 올린다. 대화 타임라인에 그대로 뜬다.
  (긴 변 1600px·JPEG 로 줄여 올린다. 원본 화질이 필요하면 카톡에서 직접 받을 것)
- **파일** — 카톡 문서는 봇이 가져오지 않는다. 대화에는 `📎 파일명` 만 남는다.
  실물은 **[자료실]** 탭에 끌어다 놓으면 그 방 자료로 쌓인다.
- 사진이 `사진 — 받지 못했다` 로 뜨면 알림이 너무 빨리 사라졌거나 전송이 끝내 실패한 것이다.
  그 자리에 무엇이 있었는지는 남는다.

## 수집이 멈췄을 때

| 증상 | 봄 |
|---|---|
| 봇 상태가 **끊김** | 폰을 본다. 메신저봇R 이 죽었거나 절전에 들어갔다 |
| 봇 상태 줄에 **⚠️ API2 꺼짐** | 레거시 프로젝트로 만든 봇이다. channelId 를 못 얻어 아무것도 안 들어온다. API2 로 다시 만든다 |
| 봇 상태는 **정상**인데 **수신 0건** 이 계속 | 메시지 이벤트가 안 온다. 알림 접근 권한·카톡 알림 설정(내용 미리보기 포함)을 본다 |
| 봇 상태는 정상, 수신은 느는데 타임라인이 안 는다 | 등록한 channelId 가 그 방이 아니다. 방 카드의 `ch …` 값과 봇 로그의 `ch=[…]` 를 대조한다 |
| "팔로우 방이 6시간 조용하다" 배너 | 그 방 카톡 알림이 꺼졌거나, 봇이 방에서 나가졌거나, 폰이 절전이다. channelId 는 저절로 안 바뀌니 다시 등록할 필요는 없다 |
| 민원 출처가 **실패 — robots.txt…** | 그 사이트가 자동 수집을 막아둔 것이다. 목록을 복사해 [붙여넣기] 로 넣는다 |
| 민원 출처가 **0건** 만 계속 | 링크 패턴이 안 맞는다. 게시판 글 주소의 특징(`nttId=`·`bIdx=` 같은 것)을 패턴 칸에 넣는다 |
| 화면의 **빌드 표식**이 방금 붙여넣은 것과 다르다 | 컴파일이 안 먹었다. 옛 스크립트가 계속 도는 중이다 |
| 로그에 **성공 줄과 실패 줄이 같이** 뜬다 | 재컴파일이 남긴 좀비 루프다. 봇을 껐다 켜거나 메신저봇R 을 완전 종료 후 재실행한다. `xn--<>-…` 주소가 보이면 주소를 채우기 전 옛 스크립트가 살아 있는 것이다 |

폰에서 직접 확인하려면 `bot/observe.js` 를 임시로 올린다. 서버로 아무것도 보내지 않고
로그만 남긴다 — `[CH]` 줄에 방마다 channelId 가, `[NOTI]` 줄에 첨부가 실렸는지가 찍힌다.
